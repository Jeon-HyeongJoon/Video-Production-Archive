# 16. 원본 드라이브 분류 사례와 판정 설계

## 1. 실측 범위

DATA 18의 탐색 revision `4740278653254714`를 기준으로 2026-11-23~24에 조사했다. 일반 폴더 1,713개(루트 제외)에서 보이는 일반 파일 17,263개를 확장자별로 셌다. 지원 영상 10,988개의 상대경로·파일명·크기를 542개 직접 상위 폴더와 대조했다. 보류 6,196개 전수와 비교군 83개에는 FFprobe로 컨테이너·스트림 헤더를 열람했다. 영상 프레임과 음성 내용은 조사하지 않았다. 아래 건수는 이 드라이브에서 발견된 사례 수이며, 촬영 내용에 대해 사람이 확인한 정답 수는 별도로 확보해야 한다.

로컬 조사 원장 `evidence/source-classification-review-20261124/file-cases.csv`는 지원 영상당 한 행에 최초 판정, 대응 원본, 측정 여부, 기술 단서, 구조 근거를 결합한다. 같은 디렉터리의 `directory-inventory.json`은 비디오 이외 항목까지 상대 폴더별 확장자 **건수**를 보존한다. 비영상 파일명과 접근을 제외한 디렉터리의 내용은 수집 범위 밖이다. 실제 업무명·개인명이 들어간 원장은 조사 환경에 보관하고 본문에는 익명화한 사례를 썼다.

보류 6,196개를 구조와 대조하면 교육 과제 19, 편집 입력 5, 편집 프로젝트 Origin 직속 2, 사전준비 2, 리허설 3, 객석 채널 후보 1 등 **32개**에 업무 용도를 붙일 수 있다. 별도 **43개**는 카메라 매체 경로까지 식별된다. 형식별 등 행사 미확인 원본·미대응 SUB 5,797개는 기존 보류, 324개에는 추가 단서가 없다. 업무 용도나 매체를 확인한 75개도 자동 렌더 승인을 얻은 수에 포함하지 않는다.

## 6. 행사 단층 배치의 반복 검증

같은 Windows 기기의 현재 Control이 반환한 READY 목록을 다시 받아 지원 영상 10,988개 전부의 상대경로와 바이트 수를 이전 원장과 대조했다. 전부 일치했다. VJ·녹화 후보 2,820개 전수에는 원본 드라이브의 읽기 전용 StorageRoot와 FFprobe로 스트림 헤더를 다시 검사했다. 이 후보군에서 헤더 검사 실패는 0건이었다. §5의 실패 13건은 별도 집합인 1차 보류 자료에서 나왔다.

| 수정한 규칙으로 전체 목록을 재생한 결과 | 직접 폴더 | 입력 영상 | 예상 결과 영상 |
|---|---:|---:|---:|

| 명시 녹화 또는 같은 행사에서 확인된 단일 위치 촬영분 6 Mbps | 20 | 20 | 20 (명시 14, 위치별 6) |
| 보류 및 프록시 제외 | 512 | 9,784 | 0 |

마지막 512폴더는 보류 506곳과 대응 프록시만 있는 6곳이다. 파일별로는 HOLD 8,623개와 대응 프록시 1,161개다. 같은 SUB 안에서도 기준을 파일마다 적용한다. 예상 목적지는 **21개 행사 폴더**이며 17개 행사에 영상 하나, 1개 행사에 두 개, 2개 행사에 세 개, 1개 행사에 다섯 개다. 대소문자 정규화 후 같은 출력 경로는 0건이었다. 이 수는 보수적인 시험 정책이 제안한 배치이며 행사 내용에 대한 정확도 측정치는 아니다.

실측 중 두 가지 오분류 경계를 발견했다.

- 날짜가 다른 두 행사에서 24컷 전체의 파일명과 크기가 대응했다. 개별 폴더의 연속 번호와 기술 규격은 모두 정상이다. 컷 순서 검증은 통과했지만 어느 행사에 속하는지 확인할 수 없어 두 행사 사이 자동 배치를 보류했다. 같은 행사의 독립된 PGM·천장·측면 녹화는 계속 처리했다.
- 한 행사 우측 카메라의 부모와 자식 모두에 긴 단일 녹화가 있었다. 이를 서로 다른 위치로 간주하면 불필요하게 두 결과가 생긴다. 같은 위치의 두 원본과 각각의 근거를 남기고 수록 범위 확인 전까지 두 건 모두 보류했다.

시험 환경의 `evidence/source-classification-review-20261124/`에는 파일별 `replay-assets.csv`, 폴더별 `replay-folders.csv`, 예상 출력만 모은 `event-layout.csv`, 집계 `replay-summary.json`이 있다. 출력 검증은 예상 계획, 목적지의 MP4 스트림·재생 시간·내장 마커, 영상별 SRT 타임스탬프, 메타데이터 checksum과 행사 목록을 대조한다. 검증 명령에는 원본 드라이브가 전달되지 않는다. ## 7. 같은 하드에서 분류 근거를 바꾼 시험

2026-11-24에 Windows Control의 READY 목록을 다시 조회했다. DATA 18의 볼륨·탐색 리비전과 영상 10,988개의 상대경로·크기·수정 시각이 §6의 목록과 일치했다. 이 목록과 기존 후보의 실측 헤더 2,820개로 시험 정책 `event-rehearsal-v1`을 147회 실행했다. 각 회차마다 보이는 파일에서 경로 분류, 컷 번호, 프록시 짝, 폴더 간 복사 의심, 행사별 목적지를 다시 계산했다. 경로 변경·입력 누락·검사 실패는 목록 사본에만 적용했다. 원본 영상 읽기와 목적지 렌더는 이번 시험에서 수행하지 않았다.

## 8. Windows에서 정책 v3 검증

2026-11-24에 DATA 18을 읽기 전용으로 두 번 탐색했다. Worker가 디렉터리와 파일 근거에서 계산한 리비전은 두 번 모두 `6565797164131617`이었다. 루트를 포함한 디렉터리 1,714개 중 542개 폴더에 지원 영상 10,988개가 있었다. 같은 카드에서 원본과 짝지은 프록시는 1,161개, 대응 원본을 찾지 못한 프록시는 136개였다. 전체 직접 영상 파일명과 크기가 다른 폴더와 대응한 폴더는 36개였다. 이 관계만으로 사본을 확정하거나 제거하지 않는다.

헤더 검사 전 단층 목적지 미리보기가 생긴 폴더는 35개였다. 이어 4개 폴더의 실제 영상 6개를 SHA-256과 FFprobe로 검사하고 같은 리비전에서 제품 분류기를 실행했다.

# 17. 원본 분류 정책과 Archivist 검토 설계

[현장 사례 전체](16-source-classification-cases.md)에서 얻은 관례를 [Archive Intake](13-archive-intake.md)의 선택·검사·결정·게시 경로에 적용한다. 새 ArchiveRun은 정책 v4와 선택 시점의 행사·채널 근거를 고정한다. 기존 결정은 당시 기록을 조회한다. ML은 별도의 오프라인 비교 실험 제안이다.

## 1. 어떤 판단을 자동화하는가

| 물음 | 판단 단위 | 의미 |
|---|---|---|
| 어디에서 나온 파일인가? | 한 탐색 revision 안의 실제 부모·형제·파일 | 촬영 카드, 편집 입력, 결과, 교육, 형식별 폴더 등 맥락을 겹쳐 기록 |
| 영상이 무슨 역할을 하는가? | 개별 파일 또는 같은 폴더의 검증된 컷열 | VJ 소스컷, 풀녹화, 프로그램/고정 채널 후보, 선별본, 파생물, 미확인. 역할과 기술 단서에는 각각 근거가 필요 |
| 지금 무엇을 할 수 있는가? | 선택된 MediaFolder의 직접 입력 전체 | 20 Mbps 합본, 6 Mbps 개별 렌더, 명시 분류 후 그대로 보관, 또는 HOLD. 보조 파일은 원본 위치에서 보존 |
| 왜 보류이며 무엇을 확인해야 하는가? | 파일·결정 revision | 확인한 사실, 반대·누락 근거, 다음 확인 방법을 Archivist와 담당자가 함께 조회 |

하나의 행사에서 VJ, PGM, 고정캠이 함께 발견돼도 형제 폴더를 하나의 입력으로 합치지 않는다. v3에서는 같은 직접 폴더에 상충하는 영상이 섞였을 때도 임의로 일부 컷만 합본하지 않는다. 파일별로 사유를 보여주되 그 폴더의 자동 작업 전체를 보류한다. 독립적인 다른 폴더는 계속 처리한다.

### 1.1 새 실행의 원본별 렌더 규격

선택된 폴더의 검사 결과를 사용해 VJ 촬영 컷은 20 Mbps, 녹화 기록은 6 Mbps로 고정한다. 같은 폴더 안에 두 역할이 있어도 각 원본에 역할, 선택한 Profile, 판단 이유와 검사 ID가 남는다. 촬영물 경로에서 이름이 남은 짧은 컷, VJ 표기, 카메라 원본명을 근거로 삼는다. 이름이 손실됐으면 촬영 맥락과 180초 이하·1920×1080 이상·영상 스트림 25 Mbps 이상을 함께 확인한다. 녹화·PGM·CLN 표기 또는 촬영물 경로의 20분 이상 유음 영상은 녹화로 처리한다. 장시간 녹화에는 SD 원본도 포함한다. 독립적인 위치 채널은 행사·형제 근거를 계속 확인한다.

직접 폴더 전체가 확인된 짧은 VJ 컷이고 순번과 기술 규격이 맞으면 기존 20 Mbps 합본과 N−1개 마커를 사용한다. 단일 컷, 순서를 알 수 없는 컷, 역할이 혼합된 폴더는 원본별 결과를 보존한다. 출력 수는 파일명 유사성이나 재생 길이로 줄이지 않는다. 노이즈 선택은 담당자가 맡으며, 확인할 수 없는 역할·편집·행사 충돌·목록 변경은 보류한다. v1~v3 실행과 명시적으로 선택한 기존 결정은 당시 선택을 재현한다.

개별 파일명에 VJ·소스컷과 PGM·녹화 역할이 동시에 명시되면 해당 폴더 전체를 HOLD한다. 예를 들어 `VJ-소스컷_PGM-녹화.mp4`에는 `FILENAME_ROLE_CONFLICT`와 검사 ID, 담당자가 원본의 역할을 확인할 다음 단계가 남는다. 같은 폴더의 다른 파일까지 실행 계획과 렌더 규격 선택을 보류한다. 일반 단어 ‘촬영’이나 영문 단어 안의 ‘pgm’만으로 반대 역할을 부여하지 않는다. `PGM_촬영.mp4`에는 기존 녹화 규격을 적용한다.

남양주 주일정오예배 테스트 폴더의 5개 검사 기록은 이름이 손실된 9~13초 MOV 3개와 길이가 약 29분인 서로 다른 MP4 2개였다. v4 결과는 개별 20 Mbps 3개와 6 Mbps 2개다. 파일 번호로 촬영 순서를 확인할 수 없다. 화면과 Archivist는 파일을 펼쳐 근거를 읽고, 예상 영상 용량은 원본별 재생 길이와 목표 비트레이트로 계산한다. `ORG-029`, `RND-007`, `DSH-054`

## 2. 관측에서 결정까지

1. **Worker 탐색.** 선택한 SOURCE_MEDIA의 읽기 전용 StorageRoot에서 디렉터리 항목을 한 번 순회한다. 정규화된 상대 폴더별로 직속 확장자와 개수를 남긴다. 빈 폴더도 한 행이다. 부모·형제는 상대경로에서 복원한다. 지원 영상만 기존 선택 목록에 포함하고 비지원 영상 후보, 카드 보조물, 보호 경계는 따로 센다. 보호·숨김·링크 아래에는 진입하지 않는다. 목록을 읽지 못하면 기존 탐색 갭을 보고한다. SCANNING 중 빈 목록을 '없음'으로 확정하지 않는다. 최종 구조와 영상 목록 양쪽이 revision에 참여하므로 빈 Output 폴더의 추가도 새 관측이다. 상세는 heartbeat와 분리된 같은 snapshot으로 보낸다. `ORG-019`
2. **구조 맥락.** 같은 드라이브와 READY revision 안에서 직접 부모, 가장 가까운 카드·프로젝트 경계, 실제 관측된 형제를 대조한다. 규칙은 정규화된 경로 구성요소에 매칭하고 근거에는 원래 상대경로를 남긴다. Source와 Output이 같은 부모라야 편집 입력·출력 관계다. 이름만 같은 다른 행사의 Output은 근거가 될 수 없다. 형식별 묶음·편집·준비·리허설 등 상위 맥락과 하위의 카메라 매체 관찰은 함께 유지한다. SUB 대응은 파일별로 같은 카드의 유일한 원본, 양수 크기와 더 작은 SUB를 확인한다. 탐색 화면의 대응은 참고용이고, 실행에서는 고정된 선택의 검사된 원본만 대응시킨다. `ORG-017`, `ORG-020`
3. **검사 비용과 관측.** 분류를 위해 프레임·오디오를 디코딩하지 않는다. 구조와 파일명으로 먼저 검토 대상을 좁히고 선택된 영상은 기존 MediaInspection에 연결한다. 해상도, 길이, 영상 스트림 비트레이트, 오디오 유무, 순번, 호환성 및 읽기 오류를 구별한다. 완전한 캐시 키는 원본 identity·checksum과 검사기 버전을 포함한다. 재실행의 검사 기록과 원래 관측 참조는 각각 유지한다. 누락된 헤더값은 미상으로 남긴다. `ORG-012`, `ORG-018`
4. **자동 결정.** v3에서는 확인된 역할과 실행 조건이 함께 있어야 한다. 행사·순서 미확인 원본, 편집 입력·결과, 행사·채널 대응이 없는 고정캠 단독, 충돌, 순서·기술정보 미확인, 유일 원본 가능성은 자동 렌더를 막는다. 역할 미상의 단일 영상이 6 Mbps 규격에 맞거나 장시간이라는 이유만으로 그대로 보관하거나 렌더하지 않는다. 이는 이름 관례가 없는 경우 기술 판정으로 내려가던 v2에서 달라지는 부분이다. 과거 v1·v2 결정과 기존 명시적 작업 옵션은 해당 버전에 고정한다. `ORG-002`, `ORG-016`, `ORG-021`
5. **사본 후보.** 완전한 목록에서 두 직접 폴더의 지원 영상 파일명·크기 다중집합이 같을 때만 폴더 전체를 사본 후보로 연결한다. 부분 일치는 완전 사본으로 표시하지 않는다. 비교는 목록 인덱스로 처리하고, 같은 후보 버킷만 실제 목록을 재대조한다. byte 일치 확인이 업무상 필요할 때만 개별 checksum을 대조한다. checksum이 일치해도 두 경로의 provenance를 보존하며 사본 표시는 작업 입력 생략·삭제 권한을 부여하지 않는다. 단, 다른 날짜의 서로 다른 행사에 동일 목록이 있으면 행사 귀속 자체가 충돌하므로 해당 결과의 자동 게시를 보류한다. 같은 행사·같은 위치의 부모·자식에 각각 장시간 파일이 있으면 별도 촬영인지 가공본인지 확인할 때까지 두 결과를 보류한다. `ORG-022`
6. **결정·게시.** 실행 결정은 ArchiveRun, 선택한 Worker·Storage·물리 장치, 입력 revision, 정책 버전, 실제 검사 ID와 근거를 고정한다. 미확인 역할은 HOLD이며 Job과 결과 패키지를 만들지 않는다. Archivist는 실제 추가 근거를 얻으면 노이즈 후보 이외의 선정된 HOLD 하나에 대해 기존 명시 분류 명령으로 새 결정을 남길 수 있다. 원래 사유를 덮어쓰지 않고 최신 decision sequence와 입력 revision을 확인한다. 동일 명령 재전송은 한 번만 반영한다. `ORG-003`, `ORG-014`, `MCP-004~005`

### 2.1 노이즈 후보 검토와 담당자의 선택

카드의 `M4ROOT/SUB`·`XDROOT/Sub` 계열, 검사에 프록시 역할이 기록된 폴더, Final Cut 라이브러리의 `Render Files` 아래 지원 영상은 직접 폴더별로 보류한다. 일반 편집 결과나 이름이 비슷한 폴더까지 일괄 제외하지 않는다. 카메라 프록시의 대응 건수는 결정에 같은 카드의 유일한 원본 경로·파일 번호 대응·크기 관계가 기록된 파일만 센다. 렌더 캐시 경로나 예전 기록의 빈 근거는 미확인으로 집계한다. `ORG-027`

Archivist는 선택된 실행의 보류 목록에서 폴더별로 대응·미확인 건수, 각 그룹의 대표 경로 최대 3개와 예외 사유별 건수, 가능한 처리 방법을 제시한다. 대응 예시는 원본 경로도 함께 보여준다. 담당자는 예외가 섞였는지 먼저 보고 필요할 때 해당 폴더의 파일별 근거를 확인한다. 화면의 초기 선택은 비어 있다. `MCP-015`, `DSH-047`

담당자는 **보류 유지**, **이번 작업에서 제외** 또는 검사값이 허용하는 보관·렌더 방식을 직접 선택한다. 선택 범위는 표시된 실행의 직접 폴더 전체다. 대응·미확인 파일이 섞인 폴더도 같은 범위를 사용한다. 분류 요청은 본 ArchiveRun·폴더·입력 revision·최신 결정 ID에 묶인다. 결정이 바뀌면 다시 선택한다. 제외 결정에는 담당자, 기존 결정 참조와 근거가 남는다. 원본은 그대로 보존하고 해당 실행의 렌더·STT·패키지·카탈로그 게시 대상에서 빠진다. Archivist의 분류 도구로는 어떤 선택도 대신 확정할 수 없다. `ORG-028`, `MCP-005`

## 3. 실행과 목적지

| 판단 | 실행 전 확인 | 목적지·결과 |
|---|---|---|
| VJ 소스 시퀀스 | 같은 직접 폴더의 원본 N개(N≥2), 전부 180초 이하, 유일하고 연속인 번호·기술 호환성. 약한 촬영 경로는 모든 파일에 고해상도·영상 스트림 비트레이트 조건도 충족. 한 컷·번호 중복·누락·규격 혼합은 HOLD | 선택된 ARCHIVE_PRIMARY에 1080p 20 Mbps 결과 하나. 입력을 번호순으로 정렬하고 누적 길이마다 N−1개 CutMarker. 첫 컷 시작에는 마커 없음 |
| 전체 녹화 | 직접 채널이 명시된 단일 PGM·CLN 등이며 상충 근거가 없음. 복수 녹화는 카메라 시점·분할 순서 확인 전 HOLD | 선택한 ARCHIVE_PRIMARY의 같은 행사 폴더에 1080p 6 Mbps 독립 영상. 다른 채널이나 VJ와 영상 자체를 합치지 않음 |
| 위치별 촬영분 | 같은 행사 아래 PGM 등 병렬 채널과 명시적인 천장·측면·메인 등 위치 표기, 단일 파일, HD·20분 이상·오디오, 편집·행사 귀속·분할 충돌 없음 | 위치당 6 Mbps 한 파일. 그 위치의 촬영분 처음부터 끝까지 보존. 다른 위치와 시작·종료 시각이 같다는 의미는 부여하지 않음. 복수 조각은 타임코드·카드 정보로 연속성이 확인될 때까지 보류 |
| 선별·기존 출력·참고 | 가공·활용 용도를 근거로 표시. 업무상 보관 요청이 있으면 명시 분류와 파일별 Profile을 사용 | 승인된 그대로 보관 경로는 QC와 provenance를 거쳐 별도 패키지로 게시 |
| 프록시·캐시·비영상·행사 미확인 | 대응·재생성 근거, 지원 여부, 누락·검사 실패를 각각 기록 | 자동 렌더 목적지 없음. 대응 원본·부모와 보류 상세는 원장에 남음 |

물리 목적지는 ArchiveRun에서 선택한 ARCHIVE_PRIMARY다. 구현된 layout v3는 결과마다 독립 폴더·패키지 하나를 만든다. 제안하는 **layout v4는 한 행사에 폴더 하나, 한 행사 폴더에 영상 여러 개**다. 날짜와 행사·장소는 원본의 의미 있는 상위 폴더에서 가져온다. CLIP, AJA, vj 같은 매체·역할명과 처리 날짜는 행사명으로 쓰지 않는다. 원본의 6자리 날짜는 그대로 유지하며 양력 연도로 추정 변환하지 않는다. 동일 제목·동일 날짜라도 서로 다른 행사 경로를 자동 병합하지 않는다. 식별이 모호하면 제안과 근거를 남기고 목적지 확정을 보류한다. `ORG-024~025`

행사 식별자는 원본 드라이브, 원래 행사명과 날짜를 담은 기준 폴더, 담당자가 확인한 동일 행사 대응에 연결한다. 이름 정규화·Windows 예약명·대소문자·경로 길이 충돌은 재실행해도 같은 식별자 접미사로 해결하고 기존 예약은 유지한다. 여러 독립 VJ 카드나 같은 위치의 독립 촬영이 있으면 검증된 직접 폴더·채널·촬영 단위마다 stem을 구별한다. 형식별 묶음·사본·다른 날짜·준비와 본행사 경계는 파일명 일부 일치로 넘지 않는다. 자막은 해당 영상의 음성에서 산출된 경우 동일 stem으로 게시한다. 무음·발화 없음·STT 대기·실패를 구별해 메타데이터와 작업 원장에 기록한다.

각 영상의 기존 package ID와 checksum·원본 및 작업 provenance를 유지하고, 상위 행사 manifest가 결과 ID와 검증된 파일을 열거한다. 위치별 독립 작업은 임시 출력·QC 후 행사 단위 잠금을 잡고 현재 manifest revision과 대조해 게시한다. 재전송은 같은 digest의 결과를 재사용하며 다른 영상·자막을 덮어쓰지 않는다. 게시 중 중단은 receipt·checksum을 대조해 복구한다. 루트 카탈로그는 영상 패키지별 행에 같은 행사 상대경로와 각기 다른 영상 상대경로를 기록하는 v4 행을 사용한다. 업그레이드는 새 실행에만 적용하며 기존 layout v1~3 복원 규칙은 버전별로 유지한다. [현재 게시 계약](04-data-archive.md)

v4 행사 manifest와 채널 메타데이터, 구형 원장 및 v2·v3 패키지와의 대조는 [목적지 메타데이터 설계](18-destination-metadata.md#4-행사별-메타데이터)에 있다.

## 4. Archivist가 인수할 근거

탐색 구조는 revision당 한 벌 저장하고 파일·결정에서는 참조한다. 운영 집계에는 탐색 범위(지원·비지원·접근 제외), 검사 성공·실패, 렌더 허용·보류 원인별 파일 및 폴더 수를 각각 표시한다. 파일명이 달라도 집계가 늘어나지 않도록 metric label은 정책·사유 코드 등으로 제한한다. 원본 경로·검사값은 선택된 작업의 상세에서 읽는다. 연결이 끊기거나 다른 revision밖에 없으면 해당 근거의 가용 상태를 표시한다. `OBS-005`, `DEV-017`, `ORG-019~026`

`archive.organization.hold.get.v1`의 v3 결정에는 정책 버전과 파일별 판정 근거를 제공한다. 예를 들어 'SUB 원본 미확인'이면 해당 카드·상대경로, 어떤 원본을 대조했는지 또는 왜 대조할 수 없는지, 같은 카드의 완료 목록을 다시 확인할 수 있는지를 반환한다. 동일 응답의 run·decision·입력 revision으로 원래 관측을 찾는다. 예전 결정에 구조 근거가 없으면 기록 당시 미수집으로 표시한다. 추정으로 소급 채우지 않는다. `ORG-023`

한 Folder Job에서 영상 두 개를 개별 게시하면 Archivist는 `PUBLISHED_PACKAGE` 행 두 개를 조회한다. 각 행은 organize 출력의 패키지 ID를 실행 명세의 원본 ID와 대조하고, 해당 원본의 역할·규격, QC 기록, 게시 메타데이터 SHA-256, StorageRoot 기준 영상 경로를 함께 반환한다. 이 경로와 파일명은 패키지와 루트 카탈로그의 영상 위치에 일치해야 한다. 기존 폴더 요약의 단일 패키지 필드는 첫 게시 ID와 그 영상명을 함께 표시한다. 합본은 순서가 고정된 원본들을 한 게시 행으로 묶는다. 후속 자막 작업은 대상 패키지 ID로 같은 영상에 연결한다.

`archive.run.status.v1`은 한 행사 내 채널별 분류·렌더·QC·보관·STT 상태를 제공한다. 진행은 실제 처리량·단위·관측 시각으로, 실패는 시도별 원인 코드·진단 기록으로, 완료는 출력 상대경로·검증 기록·manifest digest로 뒷받침한다. 게시된 영상과 자막의 품질 상태는 독립적으로 유지한다. 자막 원출력의 잘못된 UTF-8과 영상 끝을 넘는 타임코드를 정규화했다면 건수·위치·원출력 참조와 검토 상태를 남긴다. 기본 조회에는 자막 원문과 대형 예외 payload를 내보내지 않는다. 누락·중단·STT 미실행을 성공으로 환산하지 않는다. 하나의 채널이 막혀도 완료된 형제 채널의 상태와 원래 판단을 유지한다. `ORG-026`

Windows 격리 시험에서는 원본 읽기 전용 capability로 입력을 해석하고 C 볼륨의 고정된 시험 목적지만 갱신한다. 별도 evidence 디렉터리에 탐색 revision, 폴더별 결정·대응 원본, 단계 전환·진행량, 오류와 재시도, 검증된 산출물 목록·해시를 남긴다. Archivist가 시험 중과 완료 뒤 동일한 읽기 전용 명령으로 확인할 수 있다. `read-classification-test-status.ps1`의 `-ListRuns`는 시도별 목록을, `-RunId`는 이전 시도를, `-SourceFolder`는 해당 revision의 정확한 상대 폴더 하나를 조회한다. 테스트 목적지를 초기화하기 전 이전 receipt와 파일별 checksum을 대조한다. 검증 원장은 목적지 밖에 보존해 초기화 뒤에도 실패·중단·완료 시도를 조회한다. 1단계 영상 게시가 끝나도 STT가 진행 중이면 그 단계를 함께 표시한다. Windows의 native terminal에서는 아래 명령을 사용한다. 이 시험 상태는 운영 ArchiveRun과 별도의 원장이다. [시험 상태 조회 도구](../../deploy/windows/read-classification-test-status.ps1)

```powershell
powershell -NoProfile -ExecutionPolicy RemoteSigned -File C:/Archive/scratch/source-classification-rehearsal/read-classification-test-status.ps1
```

## 5. 규칙과 ML의 역할

현재는 **결정표로 실행하고, 보류 항목의 검토 순위에서만 ML을 비교**하는 안을 채택한다. 폴더 하나마다 예외를 하드코딩하지 않고 반복되는 카드 구조, 같은 부모의 업무 영역, 컷 순번, 기술 규격을 조합한다. 목록만으로 행사·순서를 복원할 수 없는 파일은 담당자나 Archivist가 더 확인할 수 있도록 남긴다.

| 선택지 | 이 자료에서 도움이 되는 지점 | 채택 조건 |
|---|---|---|
| 케이스별 규칙 | 같은 카드의 원본 대조, 마커 경계, 단일 녹화의 목적지처럼 재현 가능한 판단 | 지금 실행 기준. 규칙 ID·버전·관찰 사실로 판단을 재현 |
| ML 단독 분류 | 명명 습관이나 수치 분포가 다른 폴더의 역할을 추정 | 현재는 한 드라이브의 경로 후보와 헤더 위주라 미지의 행사에 대한 정확도 미측정. 합본·파생물 제외 권한은 결정표에서 관리 |
| 규칙 + 검토 순위 모델 | 보류 중 담당자가 먼저 보면 해소할 만한 폴더를 추천 | 실제 보류 표본에서 규칙만 쓴 순위보다 검토 효율이 높을 때 도입 |

**실험 방법.** 먼저 보류 원인별·행사별로 표본을 뽑아 담당자가 파일 역할, 행사/채널/순서 확인 여부, 판단 불가를 따로 표기한다. 운영 중 근거와 함께 확정한 명시 분류도 검토 라벨 후보로 남긴다. 규칙의 추정, 모델의 제안과 사람의 정답은 출처를 구분한다. VJ 후보 파일 수를 그대로 학습 정답 수로 쓰면 같은 이름 규칙을 재현한 성적만 얻게 된다.

첫 비교 모델은 경로 구성요소와 파일명 **패턴**, 카드·형제 구조, 파일 수·길이·영상 비트레이트·해상도·오디오·결측값으로 학습하는 간단한 선형 분류기다. 역할별 점수와 검토할 단서를 저장한다. 행사·카드·사본 관계로 연결되는 파일들은 한 그룹으로 묶어 학습과 평가에 걸치지 않게 한다. 추가 드라이브가 확보되면 통째로 떼어 일반화 성능을 측정한다. 점수를 확률로 표시하려면 별도의 보정·검증 자료가 필요하다. [그룹 분할](https://scikit-learn.org/stable/modules/cross_validation.html#group-k-fold) · [확률 보정](https://scikit-learn.org/stable/modules/calibration.html)

같은 보류 목록·동일한 검토 시간에서 규칙 순위와 모델 보조 순위를 비교한다. 상위 K개 폴더 중 실제 해소 건수, 역할별 정밀도와 표본 수, 한 건당 검토 시간, 단독 원본을 노이즈로 잘못 제시한 수를 함께 본다. 검토자가 수정한 사유와 미확인은 그대로 남긴다. 이득을 검증하기 전에는 규칙만 운영한다. 모델이 높은 점수를 준 행사 미확인 원본도 같은 행사와 순서를 입증할 때까지 합본 대상에서 제외한다. 모델 제안에는 모델·특징 버전과 관측 revision을 붙이고 자동 결정 입력과 분리한다.

작업 공간의 `event_preview`는 대상 행사 배치 제안이다. 실제 패키지 게시는 기존 layout v3를 사용한다. Archivist 상태의 `path_state`는 행사 미리보기와 게시된 패키지를 구분한다. 진행량에는 실행 중인 시도의 기록 ID와 단위를, 실패에는 원인 코드와 실패 기록 ID를, 게시에는 QC·게시 검증 참조를 제공한다. 전사 검토는 해당 작업이 기록한 품질 사유·관측 건수와 전사 산출물을 참조한다. 과거 HOLD에 파일별 근거가 없으면 `NOT_RECORDED`로 표시한다.
